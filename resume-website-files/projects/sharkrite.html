Sharkrite

An Autonomous AI Development Engine for GitHub

View on GitHub

One Command. Complete Lifecycle. Deterministically Verified.

Sharkrite runs the complete development lifecycle for a GitHub issue: isolated worktree, implementation by a Claude Code agent, PR creation, AI code review, automated triage, a full test gate, an iterative fix loop, and merge. Unattended by default. Point it at one issue, a list, or an entire label (rite --label tech-debt) and it clears the backlog while you do literally anything else.

2,600+ Automated tests 427 Issues closed 482 PRs merged 35 Custom lint rules

The Problem Being Solved

AI coding agents made writing code fast, and left everything around it manual. You still branch, push, open the PR, wait on review, triage the comments, re-run the tests, fix, re-push, and merge. Worse: an AI agent with merge rights is a liability unless something deterministic is checking its work. Sharkrite automates the ceremony and supplies the guardrails that make autonomous operation trustworthy.

Context switches: Editor, terminal, browser, CI dashboard. Dozens of hops per issue, each one breaking flow state

Self-review isn't verification: An agent grading its own work merges its own mistakes. Correctness has to come from deterministic checks (tests, lint rules, hooks), not from a model's opinion of a model

Review noise: Real findings buried between style nitpicks and false positives, lost across sessions

Backlogs don't batch: Fixing one issue at a time caps throughput at human attention span, not machine capacity

Key Features

The Test Gate

Every commit faces a polyglot gate that parses bats/TAP, jest, vitest, and pytest output, and it fails closed. A missing test runner is a hard block, never a silent pass. Skipped tests don't count as passing. A gate that can't verify refuses to merge. Targeted selection maps the diff to the tests that cover it for fast fix cycles, a full-suite pass guards merge time, and single flaky failures get exactly one bounded re-run.

Three-State Review Triage

An AI reviewer categorizes every finding, and deterministic guardrails keep the triage honest:

  • ACTIONABLE_NOW: fix in this PR. A scope bar forbids deferring the issue's own acceptance criteria.
  • ACTIONABLE_LATER: becomes a structured follow-up issue automatically, deduplicated and reconciled when the parent PR merges.
  • DISMISSED: noise, with every deferral requiring a written reason.

Model Economics by Design

Deep-reasoning models only where deep reasoning pays: Opus plans issues and reviews code, Sonnet implements, Haiku classifies. Each role's model is independently configurable, and custom lint rules make a silent fall-through to the expensive default impossible.

Every Token Earns Its Keep

Cost discipline is engineered into every layer, not bolted on. Trivial fixes skip the pipeline entirely: a cheap classifier spots issues carrying a ready-made patch and applies it deterministically, gated by the test suite alone. Dev prompts stay lean: a tag index injects only the conventions and bug patterns relevant to the issue at hand, never whole documents. Shell output is compressed before the model ever reads it, via rtk, a token-optimizing CLI proxy. And fix loops obey a convergence contract: iterations are capped and a circuit breaker trips on repeated identical failure signatures, so a stuck issue costs a bounded number of tokens instead of an unbounded loop.

AI Issue Planning

rite plan reads the project's architecture docs and ADRs and generates implementation-ready GitHub issues, enforced against an 11-section quality runbook: verified file pointers, acceptance criteria with runnable verification commands, explicit scope boundaries, and dependency chains. Filter the plan in natural language ("phases 2 through 4 except auth") and approve interactively. Issues are grounded in the docs they cite, so a dev session never starts from a hallucinated brief.

Batch Orchestration

Batches run parallel by default, with a repo-level mutex serializing concurrent invocations and a tested parity contract guaranteeing batch runs behave identically to single-issue runs. Circuit breakers halt the batch on repeated identical gate failures or provider auth loss. Stale branches rebase with lease below a divergence threshold and restart fresh above it, with LLM-assisted conflict resolution in between.

Fail-Closed Safety

Designed so the worst case is a stopped pipeline, not a damaged repo. rite --undo rolls back PR, branch, and worktree. A deterministic PreToolUse hook denies the dev agent direct access to git, gh, and destructive shell commands: enforcement lives in a script, not in a prompt. Atomic locks coordinate concurrent sessions and degrade to advisory rather than failing merged work. Review staleness is tracked by commit SHA because API timestamps race, and force-pushes are lease-only.

The Tool Builds Itself

Sharkrite has been dogfooding since v1: its own 427 closed issues and 482 merged PRs were substantially driven through its own pipeline. Beyond self-hosting, it powers a small fleet of named AI agents, each owning a different repo, that coordinate through a shared markdown message board. Field agents file bug reports with log evidence, the maintainer agent independently verifies each claim against source, ships fixes through the same gated pipeline, and confirms them live. One field finding was even formally refuted with reproduction evidence.

The operating philosophy is deterministic over model-policing-model, and it's enforced by the medium itself: every guardrail is plain bash, an inspectable script with no hidden state, so enforcement is reproducible rather than probabilistic. When an AI behavior bug recurs, it becomes a lint rule, a regression test, and a written design contract, not another prompt asking the model to behave. That policy has produced 35 custom lint rules and an 81,000-line test suite (1.7 times the size of the source it tests), run on a macOS and Linux CI matrix.

Battle Scars (or: How It Got This Paranoid)

Every fail-closed rule above traces to a real incident. Three favorites, kept because they're the best argument for the architecture:

The backlog that fought back. Planned issues sometimes described work that had already landed. Dev sessions would run, change nothing, and report failure: five sessions burned in one measured day. Sharkrite now recognizes the no-change signature, verifies the issue against main, and closes it with evidence instead of burning another session.

The symlink that ate node_modules. Worktrees once shared dependencies via symlink, until npm ci followed it and deleted the main checkout's node_modules. Reproduced, guarded, and then the design itself was removed: worktrees now bootstrap their own dependencies.

The flag that lied. The agent CLI's own tool-restriction flag was silently ignored in the production output mode. It was replaced with a deterministic deny hook that doesn't care what the model, or its CLI, thinks it's allowed to do.

Technical Decisions

Decision Choice Rationale
Language Bash (41K LOC) Zero runtime dependencies, native to every dev machine and to the agents themselves. Proof that engineering rigor is a practice, not a language feature
AI verification Deterministic gates Tests, lint rules, and hooks check the model's work. Never a second model asked to grade the first
Failure posture Fail closed Can't run the tests? Block. Runner missing? Block. Autonomous automation earns trust by refusing to guess
Provider coupling Abstraction layer Core is provider-agnostic; Claude Code is the shipped provider, not a hard dependency
Review detection Polling + SHA anchors No webhooks or servers to maintain; staleness tracked by commit ancestry because API timestamps race
