Sharkrite

An Autonomous AI Development Engine — One Command from Issue to Merged PR

View on GitHub

Type rite 42. Come Back to a Merged PR.

Sharkrite runs the complete development lifecycle for a GitHub issue — isolated worktree, implementation by a Claude Code agent, PR creation, AI code review, automated triage, a full test gate, an iterative fix loop, and merge — unattended by default. Point it at one issue, a list, or an entire label (rite --label tech-debt) and it clears the backlog while you do literally anything else.

The Problem Being Solved

AI coding agents made writing code fast — and left everything around it manual. You still branch, push, open the PR, wait on review, triage the comments, re-run the tests, fix, re-push, and merge. Worse: an unattended agent with merge rights is a liability unless something deterministic is checking its work. Sharkrite automates the ceremony and builds the guardrails that make unattended operation sane.

Context switches: Editor, terminal, browser, CI dashboard — dozens of hops per issue, each one breaking flow state

Unsupervised AI: Agents that self-review their own work merge their own mistakes — verification has to be deterministic, not vibes

Review noise: Real findings buried between style nitpicks and false positives, lost across sessions

Backlogs don't batch: Fixing one issue at a time caps throughput at human attention span, not machine capacity

Key Features

The Test Gate

Every commit faces a polyglot gate that parses bats/TAP, jest, vitest, and pytest output — and it fails closed. A missing test runner is a hard block, never a silent pass. Skipped tests don't count as passing. A gate that can't verify refuses to merge. Targeted selection maps the diff to the tests that cover it for fast fix cycles, a full-suite pass guards merge time, and single flaky failures get exactly one bounded re-run.

Three-State Review Triage

An AI reviewer categorizes every finding, and deterministic guardrails keep the triage honest:

  • ACTIONABLE_NOW — fix in this PR. A scope bar forbids deferring the issue's own acceptance criteria.
  • ACTIONABLE_LATER — becomes a structured follow-up issue automatically, deduplicated and reconciled when the parent PR merges.
  • DISMISSED — noise, with every deferral requiring a written reason.

AI Issue Planning

rite plan reads the project's architecture docs and ADRs and generates implementation-ready GitHub issues, enforced against an 11-section quality runbook: verified file pointers, acceptance criteria with runnable verification commands, explicit scope boundaries, and dependency chains. Filter the plan in natural language — "phases 2–4 except auth" — and approve interactively.

Fail-Closed Safety

Designed so the worst case is a stopped pipeline, not a damaged repo: --undo rolls back PR, branch, and worktree; --dry-run plans and exits with refusal checks in every entrypoint; a deterministic PreToolUse hook denies the dev agent direct access to git, gh, and destructive shell commands; atomic locks coordinate concurrent sessions and degrade to advisory rather than failing merged work; review staleness is tracked by commit SHA, not racy timestamps.

Model Economics by Design

Deep-reasoning models only where deep reasoning pays: Opus plans issues and reviews code, Sonnet implements, Haiku classifies. Each role's model is independently configurable, and custom lint rules make a silent fall-through to the expensive default impossible.

Batch Orchestration

Batches run parallel by default with a repo-level mutex serializing concurrent invocations, a tested batch↔single-issue parity contract, and circuit breakers that halt on repeated identical gate failures or provider auth loss. Stale branches rebase with lease below a divergence threshold and restart fresh above it — with LLM-assisted conflict resolution in between.

The Tool Builds Itself

Sharkrite has been dogfooding since v1: its own 421 closed issues and 479 merged PRs were substantially driven through its own pipeline. Beyond self-hosting, it powers a small fleet of named AI agents — each owning a different repo — that coordinate through a shared markdown message board: field agents file bug reports with log evidence, the maintainer agent independently verifies each claim against source, ships fixes through the same gated pipeline, and confirms them live. One finding was even formally refuted with reproduction evidence. Peak measured throughput on a production monorepo with ~4,500 tests: 17 autonomous issue merges in a single day, cutting the backlog from 141 to 42.

The operating philosophy is deterministic over model-policing-model: when an AI behavior bug recurs, it gets converted into a lint rule, a regression test, and a written design contract — not another prompt asking the model to behave. That policy has produced 35 custom lint rules and an 81,000-line test suite (1.7× the size of the source it tests), run on a macOS + Linux CI matrix.

Battle Scars (or: How It Got This Paranoid)

Every fail-closed rule above traces to a real incident. Three favorites, kept because they're the best argument for the architecture:

The dry run that wasn't. --dry-run turned out to be "born dead" — parsed but never wired — discovered when a dry run executed for real. It was rebuilt fail-closed: plan-and-exit, with independent refusal checks in every execution path.

The symlink that ate node_modules. Worktrees once shared dependencies via symlink — until npm ci followed it and deleted the main checkout's node_modules. Reproduced, guarded, and then the design itself was removed: worktrees now bootstrap their own dependencies.

The flag that lied. The agent CLI's own tool-restriction flag was silently ignored in the production output mode. Replaced with a deterministic deny hook that doesn't care what the model — or its CLI — thinks it's allowed to do.

Technical Decisions

Decision Choice Rationale
Language Bash (41K LOC) Zero runtime dependencies, native to every dev machine and to the agents themselves — proof that engineering rigor is a practice, not a language feature
AI verification Deterministic gates Tests, lint rules, and hooks check the model's work — never a second model asked to grade the first
Failure posture Fail closed Can't run the tests? Block. Runner missing? Block. Unattended automation earns trust by refusing to guess
Provider coupling Abstraction layer Core is provider-agnostic; Claude Code is the shipped provider, not a hard dependency
Review detection Polling + SHA anchors No webhooks or servers to maintain; staleness tracked by commit ancestry because API timestamps race
